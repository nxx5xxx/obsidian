###### 동적타이핑
#동적타이핑
**예시**
정적타이핑
```
int number = 5;
```
동적타이핑
```
def number = 10
str = "Hi"
```
최상단과 같이 타입을 미리 지정해주고 해당하는 타입만 가능한것이 정적타이핑
두번째 예시와 같이 변수명에 정의만 해준고 실행시 타입이 지정되는것이 동적 타이핑이다
장점으로는 코드가 간결해지고 작성속도가 빠르고 단점으로는 타이핑실수가 컴파일 시 걸러지지않고 프로그램 실행중에 오류가 발생할 수 있다는것

## 타입
Gradle-Groovy , Gradle-Kotlin, Maven 세개가 존재한다 (2026.1 버전기준)
이전에는 Gradle과 Maven 두가지로만 있었는데 Gradle이 두개로 분류되었다
Groovy와 Kotlin 두가지의 차이를 구분할 땐
스크립트 확장자명에서 그분이 가능하다
```
Groovy : build.gradle
Kotlin : build.gradle.kts
```
Groovy는 동적타이핑 특성에 의해 빌드시점에서 오류를 알 수 있고
Kotlin DSL은 실시간 문법검사 및 안전한 리팩토링이 가능해서 Kotlin DSL을 사용하는 추세라고 한다
Maven은 뭐 예전에 사용하던 그대로 XML기반으로 작성된다
개인적으로 Maven이 익숙해서 편한데 많이들 사용하는 Gradle 을 사용할 것이고 Groovy로 사용할것이다 Kotlin은 추후에 해보기로한다

## 그룹
프로젝트를 고유하게 식별하기위해 도메인주소의 역순 이라고 설명되어 있기는 한데
후에 변경 가능하기도 하지만 웬만하면 맞춰주는것이 낫다 Maven기준으로 pom.xml을 건드려줘야하는데 이게 좀 오류가 많이 터졌던걸로 기억한다.

## 아티팩트
프로젝트 이름이라고 보면된다 후에 Build하면 Jar나 War파일이 이태픽트이름으로 결과물이 나온다
그룹이 회사 조직 등을 나타낸다면 Artifact는 그회사에서 만드는 특성 프로젝트 등을 의미한다
예 : com.회사명.artifact명
예2: com.navxx.shopping
### 작성규칙
소문자로만 작성하며 단어사이는 하이픈으로 연결하는것이 관례
예 : shop-api , member-service , chatbot-project

## 패키지이름
그룹+아티팩트가 패키지이름이 된다
예: 그룹 com.navxx 아티팩트 shopping
-> com.navxx.shopping

스프링의 자동탐색은 패키지를 기준으로 컴포넌트 스캔한다 (등록하고 실행한다)

## 패키지생성
JAR와 WAR로 나뉜다
### JAR
Java Archive(자바보관소)의 약자
Java Class파일, 구성파일, 리소스 등이 들어있으며 내장 웹서버가 포함되어있다
War에서는 내장 웹서버가 포함되어있지 않다.
내장웹서버(톰캣)이 내장되어있어 별도의 서버 설치가 불필요하며
JRE(자바실행환경)만 있으면 java -jar 파일명.jar 명령어로 웹서비스를 바로 실행 가능하다
- 스프링부트 프로젝트의 기본 권장사항
- AWS나 MSA 환경에서 가장 선호되는 방식이라고 한다

### WAR
Web Application Archive(웹애플리케이션보관소)의 약자
웹애플리케이션(JSP,서블릿,HTML,cSS 등) 이 포함되어 있다
내장웹서버가 없으므로 외장 웹서버가 있어야 실행이 가능하다
- 이미 구축 되어있는 대형 외부 웹 서버에 프로젝트 파일만 가볍게 올려서 배포가 가능
- 레거시 프로젝트, JSP를 사용해야하는 프로젝트, WAS인프라가 구축되어 있는경우 주로 사용한다
